D2. steering correction과 speed/brake correction 분리 loss
현재 action은 [steer, longitudinal]이고 longitudinal은 양수 throttle, 음수 brake다. recovery loss도 action dim별로 분리
해야 한다.
m_early = (route_progress <= 0.10)
m_severe = m_early & ((abs(lane_offset) >= 1.2) |
 (abs(heading_error_deg) >= 10.0))
m_fast = m_severe & (speed_kmh >= 16.0)
delta_steer_target = corrected_steer - policy_steer
delta_long_target = corrected_longitudinal - policy_longitudinal
delta_steer_pred = pred_steer - policy_steer
delta_long_pred = pred_longitudinal - policy_longitudinal
추천 loss
L_early_steer_delta =
 mean(w_side * m_severe * huber(delta_steer_pred - delta_steer_target,
 delta=0.05))
L_early_steer_sign =
 mean(w_side * m_severe * relu(margin_s - sign(delta_steer_target) *
 delta_steer_pred))
L_early_long_delta =
 mean(m_fast * huber(delta_long_pred - delta_long_target, delta=0.05))
# high-speed lateral recovery 중에는 throttle 제한
L_early_throttle_cap =
 mean(m_fast * relu(pred_longitudinal - 0.06) ** 2)
# brake가 필요한 경우 pred_longitudinal <= -brake_margin 유도
L_early_brake_margin =
 mean(m_fast * relu(pred_longitudinal + brake_margin) ** 2)

E. PPO를 재개해도 되는 조건
지금 상태에서는 PPO를 재개하면 안 된다. Round29는 guard+smoothing 512 eval에서 PPO gate를 통과했지만, PPO
2048에서 offroad 7, collision 1이 다시 발생했다. 이는 BC deterministic gate가 PPO rollout distribution을 대표하지 못
한다는 증거다.
PPO 재개 전 필수 조건
1. raw BC 512: collision 0, offroad 0, early/severe early offroad 0
2. raw BC 2048: collision 0, offroad 0, early/severe early offroad 0
3. guard BC 512/2048: raw 실패를 guard가 완전히 덮는 구조가 아닐 것
4. positive-lane sign rate >= 0.75, negative-lane sign rate >= 0.75
5. high-speed severe lateral error에서 throttle cap violation <= 5%
6. mean_action_jitter <= 0.07
7. collision이 있는데 fail_reasons가 비는 gate loophole 없음
8. maneuver fixed-straight와 cycle에서 초기 route heading, heading_error, steer sign이 설명 가능
PPO 재개 시 보수적 설정
ppo:
 learning_rate: 0.000002 # 기존 0.000005보다 더 보수적으로 시작
 clip_coef: 0.03 # 기존 0.06보다 작게
 update_epochs: 1
 max_grad_norm: 0.5
 target_kl: 0.01
 abort_rollout_on_offroad: true
 abort_rollout_on_collision: true
 freeze_rgb_perception: true # 초기 N update
 freeze_actor_input_adapter: true # 초기 N update
 critic_warmup_updates: 3
 imitation_anchor_on_failure_transitions: true
PPO update마다 before-update deterministic eval, after-update deterministic eval, after-update stochastic eval,
offroad/collision transition replay imitation anchor, KL early stop을 강제한다. PPO가 다시 offroad를 만들면 reward 문
제로만 보지 말고 BC anchor가 없는 actor drift와 critic이 early offroad의 장기 cost를 과소평가하는 문제로 봐야 한다.

F. lateral recovery guard를 논문/보고서에서 공정하게 다루는 방법
Round29 기준으로 lateral recovery guard는 아직 성능을 조금 보강하는 safety layer라기보다 raw policy 실패를 가리는
hand-coded controller에 가깝다. raw 512 eval은 offroad 7, early/severe early offroad 7이었지만 guard 512 eval은
offroad 0과 max route 0.564103을 만들었다. 즉 현재 성능 차이의 큰 부분이 learned policy가 아니라 runtime correction
에서 나온다.
보고서에 분리해서 제시할 조건
- RCS-AC raw
- RCS-AC + smoothing only
- RCS-AC + lateral recovery guard
- RCS-AC + lateral recovery guard + speed gate
- PPO/attention baseline + 동일 guard
- SAC/TD3/attention baseline + 동일 guard
guard를 안전층으로 유지해도 되는 조건
- raw policy가 이미 collision 0, offroad 0, early offroad 0을 만족
- guard intervention rate <= 10-15%
- mean abs steer correction <= 0.03-0.05
- max correction 0.22가 매우 드물게만 발생
- guard on/off 성능 차이가 route progress 기준 0.10 이하
- 동일 guard를 baseline에도 적용했을 때 RCS-AC의 상대 우위가 유지
보고서 문장 예시
Lateral recovery guard는 학습 정책의 일부가 아니라 runtime safety layer로 사용하였다. 따라서 본문 주요 성능은 raw policy와
guard-assisted policy를 분리해 보고하고, 모든 baseline에 동일 guard를 적용한 공정 비교를 함께 제시하였다.
현재 Round29 결과를 그대로 쓰면 결론은 다음과 같다: Raw RCS-AC는 아직 early route recovery를 학습하지 못했다.
Guard+smoothing은 early offroad를 막지만 policy 성능을 가린다. 따라서 다음 라운드의 성공 기준은 guard 성능이 아니라
 raw BC 512/2048의 early/severe offroad 0이다.
